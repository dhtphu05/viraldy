## 1. Findings that determine the V2 design

1. **Current Unifically rendering submits the uploaded target product image and text, not the reference video or source frames.** The source video's information reaches generation through `ReferenceAnalysis`, scene/shot plans and compiled prompts. `_render_with_unifically` uploads only `productImage`, uses object reference mode, and leaves `imageRequestIds` empty. This is reference-image-conditioned new video generation, not demonstrated video editing. [Submission path](../../apps/backend/src/viraldy/modules/smart_remake/engine/render_orchestrator.py#L367), [payload builder](../../apps/backend/src/viraldy/modules/smart_remake/engine/unifically_adapter.py#L779).
2. **Gemini does receive the actual source video during live analysis.** Its separate product analysis request receives the target image. Receiving video for analysis does not mean the video generator receives video. [Reference media call](../../apps/backend/src/viraldy/modules/smart_remake/engine/reference_analyzer.py#L234), [product media call](../../apps/backend/src/viraldy/modules/smart_remake/engine/product_lock_generator.py#L68).
3. **FlowKit is an external generation bridge.** The repository creates a project/product visual asset and scenes, then submits `GENERATE_IMAGE` followed by `GENERATE_VIDEO`. No model ID, resolution, duration, or explicit start image is in those generation request objects. The exact downstream Google Flow model and image-to-video handoff cannot be established from this repository alone. [Preparation](../../apps/backend/src/viraldy/modules/smart_remake/engine/flowkit_adapter.py#L82), [request builders](../../apps/backend/src/viraldy/modules/smart_remake/engine/flowkit_adapter.py#L193).
4. **The configured Unifically image model and image-generation builder are currently dormant in production source.** `get_unifically_image_model` and `build_unifically_image_input` exist, but current render imports/calls only the video builder. Source-frame extraction remains implemented even though the current video submission omits these frames. [Image model selector](../../apps/backend/src/viraldy/modules/smart_remake/engine/config.py#L103), [image builder](../../apps/backend/src/viraldy/modules/smart_remake/engine/unifically_adapter.py#L723), [render imports](../../apps/backend/src/viraldy/modules/smart_remake/engine/render_orchestrator.py#L31), [frame attachment](../../apps/backend/src/viraldy/modules/smart_remake/engine/compile_service.py#L139).
5. **There is no separate human character-image generation input in the current Smart Remake render contract.** FlowKit's “character” is the product with `entity_type="visual_asset"`; the dormant Unifically character-reference branch also uses the product image. These are not evidence of actor identity preservation or replacement. [Render contract](../../apps/backend/src/viraldy/modules/smart_remake/engine/schemas.py#L429), [product character](../../apps/backend/src/viraldy/modules/smart_remake/engine/flowkit_adapter.py#L126), [dormant character branch](../../apps/backend/src/viraldy/modules/smart_remake/engine/unifically_adapter.py#L827).

## 3. Exact transport and payload contracts

### 3.1 Gemini: actual multimodal analysis, JSON output

`HttpGeminiClient._request_text` posts to the public endpoint:

```text
POST https://generativelanguage.googleapis.com/v1beta/models/{get_gemini_model()}:generateContent
Query: key=<GEMINI_API_KEY; redacted>
```

```json
{
  "system_instruction": {"parts": [{"text": "<system instruction>"}]},
  "contents": [{"role": "user", "parts": [
    {"text": "<analysis prompt>"},
    {"inline_data": {"mime_type": "<actual media MIME>", "data": "<base64 media bytes>"}}
  ]}],
  "generationConfig": {
    "responseMimeType": "application/json",
    "temperature": 0.1,
    "maxOutputTokens": 16384
  }
}
```

The media part is optional at client level; the public compile service requires both a video and product image. Reference analysis gets the whole uploaded video bytes in one request; product analysis gets product image bytes in a separate request. The compiler itself is deterministic and makes no third semantic generation call. No Gemini Files API upload, explicit frame sampling rate, or generated-output video verification call is present in this client. [Payload and endpoint](../../apps/backend/src/viraldy/modules/smart_remake/engine/gemini_client.py#L176), [reference call](../../apps/backend/src/viraldy/modules/smart_remake/engine/reference_analyzer.py#L251), [product call](../../apps/backend/src/viraldy/modules/smart_remake/engine/product_lock_generator.py#L90), [compile order](../../apps/backend/src/viraldy/modules/smart_remake/engine/compile_service.py#L102).

Viraldy's admission rules accept reference `video/mp4`, `video/webm`, `video/quicktime` and product `image/jpeg`, `image/png`, `image/webp`; default upload limits are 30 MiB video and 10 MiB product image. These are application MIME/size checks, not a verified provider modality specification or duration guarantee. The input check does not decode the media here. [Checks](../../apps/backend/src/viraldy/modules/smart_remake/engine/media_validation.py#L6), [limits](../../apps/backend/src/viraldy/modules/smart_remake/engine/config.py#L4).

`generate_json` extracts candidate text, parses JSON with limited comma repair, and resends the original media once with a JSON-correction prompt if parsing still fails. Schema normalization happens outside this client. It does not save provider usage metadata, response model version, request ID, raw successful response, cost or per-call latency to a model-run record. [Parse/repair](../../apps/backend/src/viraldy/modules/smart_remake/engine/gemini_client.py#L74), [semantic retry](../../apps/backend/src/viraldy/modules/smart_remake/engine/gemini_client.py#L130), [response extraction](../../apps/backend/src/viraldy/modules/smart_remake/engine/gemini_client.py#L255).

### 3.2 Unifically: product-reference-conditioned video

Public default bases are `https://api.unifically.com` and `https://files.storagecdn.online`; deployment overrides are `UNIFICALLY_API_BASE_URL` and `UNIFICALLY_FILES_BASE_URL`. Private override URLs and all credentials are intentionally excluded. [Configuration](../../apps/backend/src/viraldy/modules/smart_remake/engine/config.py#L8).

| Operation | Exact request contract |
| --- | --- |
| Upload target product | `PUT {files_base}/upload`, `Authorization: Bearer <redacted>`, multipart `file=(filename, productImage.bytes, productImage.mime_type)`; requires returned `file_url`. [Client](../../apps/backend/src/viraldy/modules/smart_remake/engine/unifically_client.py#L34) |
| Create generation | `POST {api_base}/v1/tasks`, Bearer token, JSON `{"model": "<get_unifically_video_model()>", "input": <payload below>}`; requires returned `task_id`. [Client](../../apps/backend/src/viraldy/modules/smart_remake/engine/unifically_client.py#L59) |
| Status | `GET {api_base}/v1/tasks/{task_id}`, Bearer token. [Client](../../apps/backend/src/viraldy/modules/smart_remake/engine/unifically_client.py#L75) |
| Output | `GET <returned output URL>`; redirects followed, bytes buffered in memory. URL is provider data, not a fixed endpoint. [Download](../../apps/backend/src/viraldy/modules/smart_remake/engine/unifically_client.py#L86) |

The current initial/repair submission is:

```json
{
  "model": "google/veo-3.1-lite-relaxed",
  "input": {
    "aspect_ratio": "9:16",
    "duration": 8,
    "seed": "<non-negative configured or derived integer; omitted on fallback>",
    "reference_image_urls": ["<uploaded target-product URL>"],
    "prompt": "<compiled identity, shot/segment, pacing and scene instructions>"
  }
}
```

`seed` is actually an integer; its placeholder above describes its source. The model ID may be overridden. The seed defaults to CRC32 of product bytes plus sorted ProductLock JSON, shared across scenes, or `SMART_REMAKE_UNIFICALLY_SEED`. A seed is not an evidence-based identity/temporal consistency guarantee. The retry rebuilds without a seed. [Seed](../../apps/backend/src/viraldy/modules/smart_remake/engine/render_orchestrator.py#L113), [initial submission](../../apps/backend/src/viraldy/modules/smart_remake/engine/render_orchestrator.py#L373), [retry](../../apps/backend/src/viraldy/modules/smart_remake/engine/render_orchestrator.py#L399).

The following do **not** appear in the current submitted input: source video URL/bytes, extracted source frame URLs, generated scene-frame URL, previous scene video, separate human identity image, segmentation mask, tracked object trajectory, optical flow, depth/pose conditioning, output resolution, frame rate, or a structured voice/audio request. Product geometry, physical action, shot/camera timing and native audio directions are requested through text. Their successful realization is not independently verified by this adapter. [Current call arguments](../../apps/backend/src/viraldy/modules/smart_remake/engine/render_orchestrator.py#L377), [allowed input keys](../../apps/backend/src/viraldy/modules/smart_remake/engine/unifically_adapter.py#L11), [returned input](../../apps/backend/src/viraldy/modules/smart_remake/engine/unifically_adapter.py#L779).

The video builder allows up to 5,000 prompt characters, 9:16 only, at most three image ingredients counting both `reference_image_urls` and all character `image_urls`, and duration exactly 8 when references exist. It rejects simultaneous `start_image_url` and reference images. These are implemented request checks, not independently confirmed provider maximums. `end_image_url`/`voice` are allowlisted but not emitted by the builder. [Validator](../../apps/backend/src/viraldy/modules/smart_remake/engine/unifically_adapter.py#L639).

## 5. Retry, timeout, paid-job duplication and observability

## 6. Other image/video and analysis adapters outside Smart Remake

### Generic generation gateway

`HttpGenerationProvider` sends:

```text
POST {AI_BASE_URL}/media/generations
Authorization: Bearer <AI_API_KEY; redacted>
```

```json
{
  "model": "<IMAGE_GENERATION_MODEL or VIDEO_GENERATION_MODEL>",
  "operation": "<storyboard_image_generate or concept_video_preview_generate>",
  "generation_run_id": "<UUID>",
  "brief": "<GenerationBriefV1 object>"
}
```

`brief` is an actual JSON object. It contains text/camera/creator directions, aspect ratio, optional duration, constraints and **asset UUIDs**, not loaded media bytes, signed media URLs, source frames or video. Source assets are validated for workspace ownership in the surrounding service, but the provider adapter does not resolve their media. An independently deployed custom gateway might resolve UUIDs; that behavior is not in this repository's adapter and is not established here. Consequently, classify this as a custom brief-to-artifact gateway, not verified I2V/V2V/object replacement. [Transport](../../apps/backend/src/viraldy/modules/generation/provider.py#L165), [brief schema](../../apps/backend/src/viraldy/modules/viral_kits/contracts.py#L246), [asset validation/enqueue](../../apps/backend/src/viraldy/modules/generation/service.py#L95).

The generic live adapter requires configured image/video model names and rejects missing model configuration. Returned artifacts must conform to `GenerationProviderResultV1` and reject persisted remote/signed URLs; the contract expects storage keys and metadata. There is no vendor-specific Sora/Kling/fal/Replicate video execution adapter established by the inspected application source. Fixture artifacts declare image/video sizes (e.g. 1080×1920) but their media type is `application/vnd.viraldy.fixture+json` and their storage key is null. These dimensions are synthetic metadata. [Selection](../../apps/backend/src/viraldy/modules/generation/provider.py#L215), [artifact validation](../../apps/backend/src/viraldy/modules/generation/contracts.py#L27), [fixtures](../../apps/backend/src/viraldy/modules/generation/provider.py#L68).
